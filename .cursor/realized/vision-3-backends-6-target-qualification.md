## Reference pattern

[Image.hx](../../src/vision/ds/Image.hx) exposes the current canvas conversions. [ImageTools.hx](../../src/vision/tools/ImageTools.hx) provides the existing `addToScreen` API.

## Steps

### 1. Exercise existing entry points

Use the Canvas 2D path from the existing canvas export and `addToScreen` methods. Verify a round trip and the rendered pixels from the normal public calls.

### 2. Qualify additional outputs and the preview compiler

Compile Flash and HashLink/C with the existing image API. Run the smoke programs using a Flash-compatible runtime and a linked HashLink/C executable. Use explicit point construction where required by the pinned Haxe 5 preview and verify the existing behavior suite.

## Verification

- Require all 12 Haxe 4.3.7 CI jobs on the draft PR.
- Run the [browser fixture](../../tests/ci/drawing.html) and the [extra target smoke tests](../../tests/ci/framework-drawing.md).
- Run `haxe test.hxml` and check the browser fixture compilation on Haxe 5.0.0-preview.1.

## Implementation and evidence

- The existing `toJsCanvas` and `ImageTools.addToScreen` paths use the Canvas 2D backend. Canvas imports convert RGBA to Vision's packed ARGB. Edge verified a non-square round trip, canvas position, and actual drawn pixels.
- Haxe 4.3.7 and Haxe 5.0.0-preview.1 both passed all 619 interpreter tests and compiled the browser fixture. The preview also selected a `.js.hx` module for JavaScript and the plain `.hx` module for interpreter execution.
- The Flash smoke ran in Ruffle 0.7.1 on Edge. HashLink/C was generated by Haxe 4.3.7, compiled and linked with MSVC against HashLink 1.16, and ran the image smoke on Windows. [Reproduction](../../tests/ci/framework-drawing.md)
- The GitHub Actions matrix covers interpreter, Neko, HashLink bytecode, JavaScript/Node, C++, JVM, Python, Lua, PHP, C#, Java source, and CPPIA on Haxe 4.3.7. The draft PR records the checks for the final revision. [PR #58](https://github.com/ShaharMS/Vision/pull/58)
